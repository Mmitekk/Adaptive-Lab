# Adaptive Lab

Монохромная лаборатория адаптивности: настоящий Chromium, снимки страниц, подсветка проблемных элементов, сравнение экранов, история и экспорт PNG/JSON/HTML. Независимые эвристики, а не закрытый алгоритм Яндекс.Вебмастера.

## GitHub Pages + Actions

Pages раздаёт интерфейс и готовые отчёты. Node.js и Chromium выполняются отдельно в GitHub Actions: обычный посетитель Pages не может запустить проверку без прав на репозиторий. Токенов и формы ввода PAT в интерфейсе нет.

### Первое включение

1. В репозитории `Mmitekk/Adaptive-Lab` откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**. Проверьте, что Actions разрешены настройками репозитория/организации.
2. Отправьте локальный коммит в ветку `main` самостоятельно. Push запустит `.github/workflows/pages.yml`: установка зависимостей, тесты, сборка и публикация Pages. Если первый запуск был до включения Pages, повторите workflow вручную без URL.
3. Дождитесь успешных заданий **build** и **deploy**. Адрес сайта появится в **Settings → Pages** и в окружении **github-pages** завершённого запуска.
4. Первая публикация содержит пустую историю. Существующие локальные `data/` и снимки с компьютера не попадают ни в Git, ни на Pages.

Для первого развёртывания могут понадобиться права администратора репозитория. На ветке `main` должен находиться workflow. Другие ветки публикацию не выполняют.

### Проверка сайта

1. На Pages введите адрес, выберите размеры и режим, нажмите **Проверить через Actions**.
2. Диалог покажет параметры. **Открыть GitHub Actions** только открывает страницу workflow — это ещё не запуск и параметры не подставляются автоматически.
3. На GitHub войдите с правами записи в репозиторий, нажмите **Run workflow**, выберите `main` и перенесите значения:

   | Поле | Значение |
   |---|---|
   | `url` | Полный публичный HTTP(S)-адрес; пустое поле — только обновить публикацию |
   | `width`, `height` | Целые числа 280–2560; по умолчанию 390 × 844 |
   | `mode` | `quick` — выбранный экран; `full` — выбранный плюс 320, 375, 768, 1440 px без дублей |
   | `mobile` | Мобильный User-Agent и касания для выбранного экрана |
   | `publish` | Явное согласие опубликовать URL, отчёт и снимки; по умолчанию **false** |

4. Запускайте только страницы, на проверку которых у вас есть разрешение. Без `publish=true` аудит с URL завершится ошибкой, прежняя публикация сохранится. Не передавайте секретные ссылки, персональные или конфиденциальные данные.
5. Дождитесь зелёных **build** и **deploy**, вернитесь на Pages и нажмите **Обновить отчёты**. Откройте результат из истории. Есть очередь и лимиты GitHub Actions; проверка занимает до 4 минут плюс установка браузера, сборка и публикация.

Параметры передаются процессу через переменные окружения, не через подстановку URL в shell. Build имеет только `contents:read` / `actions:read`, отдельное deploy-задание — `pages:write` / `id-token:write`. Стандартный `GITHUB_TOKEN` используется только runner, не браузерным интерфейсом. Параллельные публикации сериализованы; GitHub может заменить уже ожидающий запуск более новым.

### История и приватность

- Публикуются до **20 отчётов / 200 МиБ**, один отчёт — до **32 МиБ**. Полные снимки входят в JSON; загрузка большого отчёта может занять время.
- История переносится между успешными запусками `pages.yml` на основной ветке через артефакт `adaptive-lab-reports`. Просматриваются последние 30 успешных запусков; срок артефакта — до 90 дней, ограниченный политикой GitHub/организации. Если подходящего артефакта больше нет, следующая публикация начнёт историю заново. Уже опубликованная Pages-версия сама по таймеру не меняется.
- Это не личное хранилище. Посетителям доступны URL, заголовок, найденные элементы, ошибки ресурсов и изображения. Скачивайте нужные результаты через экспорт.
- Кнопки удаления в Pages нет. Чтобы очистить текущую публикацию, владелец удаляет **все** артефакты `adaptive-lab-reports` и выполняет workflow без URL. При необходимости отдельно удалите старые Actions-артефакты `github-pages` и журналы запусков; уже скачанные копии и внешние кеши отозвать невозможно.
- Сборка Pages использует только `.pages-reports/` и `.audit-output/`, не читает локальную историю `data/`. Эти каталоги, сборки, логи и `.env` исключены из Git.

## Локальная версия

Нужны Node.js 24 и npm. На Windows автоматически используются установленные Chrome или Edge. Иначе установите браузер командой `npx playwright install chromium` (на Linux — `npx playwright install --with-deps chromium`).

```sh
npm ci
npm run build
npm start
```

Windows: после `npm ci` файл `Start-Adaptive-Lab.cmd` собирает проект, если сборки ещё нет, и запускает сервер в фоне. `node start.js --no-open` делает то же без открытия браузера. После изменения исходников пересоберите `npm run build`. Адрес записывается в `.runtime.json`.

Сервер слушает только `127.0.0.1`, по умолчанию пробует порты 4177–4196. Занятые порты пропускаются, чужие процессы не завершаются. `PORT` задаёт начало диапазона. Локальный API не предназначен для публикации во внешнюю сеть.

```sh
npm run dev
npm test
npm run build:pages
npm run preview:pages
```

Последняя команда показывает **статическую** сборку на `http://127.0.0.1:4188/Adaptive-Lab/`, без API. Если порт занят, она завершится с ошибкой, не затронув listener; выберите другой `PORT`.

Браузерный регрессионный тест локальной версии (при запущенном сервере; синтаксис Git Bash):

```sh
TEST_URL=http://127.0.0.1:4177 node --test tests/ui.test.js
```

Для локальной проверки полного Actions-пути без отправки данных на GitHub (Git Bash):

```sh
AUDIT_URL=https://narkorating.ru/ AUDIT_MODE=full AUDIT_PUBLISH=true npm run audit:actions
npm run build:pages
npm run preview:pages
```

Команда аудита записывает только локальный `.audit-output/`. Публикацию выполняет отдельное задание GitHub Actions. После получения полного отчёта можно запустить `TEST_PAGES_URL=http://127.0.0.1:4188/Adaptive-Lab/ node --test tests/pages.test.js`; UI-сценарий проверяет историю, диалог, снимки, экспорт, отсутствие API/POST и размеры 320–2560 px. Без переменных `TEST_URL` / `TEST_PAGES_URL` UI-сценарии пропускаются, модульные и серверные тесты выполняются.

## Что измеряется

Viewport, горизонтальное переполнение, ширина изображений, устаревшие плагины, HTTP-ответ, мелкий текст, цели нажатия, запрет масштабирования и ошибки ресурсов. Оценка 0–100 относится к выбранному экрану; это не сертификация WCAG, Core Web Vitals или заключение Яндекса.

Каждый экран открывается в чистом Chromium-контексте с sandbox. GET/HEAD только к публичным HTTP(S) адресам на портах 80/443; приватные сети, DNS rebinding, WebSocket, service workers и отправка форм заблокированы. Единственное локальное исключение — встроенный `/demo.html`. Redirect и запросы ресурсов перепроверяются через аутентифицированный прокси с закреплением проверенного IP.

Не проверяются авторизованные страницы, CAPTCHA, внутренности iframe/Shadow DOM и интерактивные состояния. Защиты сайтов не обходятся. Chromium в размере iPhone — не Safari. Снимок ограничен 4096 × 10000 px; lazy-контент и страницы, требующие POST/WebSocket, могут загрузиться не полностью. Интерфейс на десктопе имеет увеличенную типографику без увеличения h1, на QHD — расширенную рабочую область.
